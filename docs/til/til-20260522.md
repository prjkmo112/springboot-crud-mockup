### JPA Auditing (@CreatedDate / @LastModifiedDate)

엔티티에 생성일시, 수정일시를 자동으로 채워주는 기능이다. 직접 `LocalDateTime.now()` 넣는 게 아니라 Spring Data JPA가 알아서 처리해준다.

**설정 방법**

1. 애플리케이션 진입점에 `@EnableJpaAuditing` 붙이기

```java

@SpringBootApplication
@EnableJpaAuditing
public class MainApiApplication {
}
```

2. 엔티티 클래스에 `@EntityListeners(AuditingEntityListener.class)` 붙이기

```java

@Entity
@EntityListeners(AuditingEntityListener.class)
public class Order {
    @CreatedDate
    private LocalDateTime createdAt;

    @LastModifiedDate
    private LocalDateTime modifiedAt;
}
```

`@EnableJpaAuditing`만 붙이고 엔티티에 `@EntityListeners`를 빠뜨렸더니 날짜가 안 채워졌다.
Auditing 기능은 리스너가 엔티티 생명주기 이벤트를 감지해서 값을 넣어주는 방식이라, 엔티티에 리스너 등록을 명시해줘야 동작한다.
두 어노테이션이 세트라는 걸 기억해두자.

### JWT 기반 로그인 구현

세션 없이 JWT 토큰으로 인증 상태를 유지하는 stateless 방식으로 구현했다.

**전체 흐름 요약**

```
[회원가입]  POST /auth/register  →  비밀번호 BCrypt 암호화 후 DB 저장
[로그인]    POST /auth/login     →  AuthenticationManager로 인증 → JWT 발급 → 쿠키에 저장
[인증 확인] POST /auth/check     →  쿠키에서 토큰 꺼내서 유저 정보 반환
[매 요청]   OncePerRequestFilter →  토큰 검증 → SecurityContext에 유저 세팅
```

**JWT 토큰 생성 (`JwtTokenService`)**

- 서명 알고리즘: HS512
- subject에 `email::username` 형태로 저장
- 만료 5분 전이면 `refreshToken()`에서 자동 재발급

**토큰 전달 방식**

쿠키(`X-Auth-Token`)로 내려준다. `HttpOnly + Secure + SameSite=None` 설정을 했는데, XSS로 토큰을 탈취당하지 않도록 JS에서 접근 불가능하게 하는 게 목적이다. 쿠키가
없으면 헤더(`X-Auth-Token`)도 fallback으로 확인한다.

**필터 (`AuthenticationProcessingFilter`)**

`OncePerRequestFilter`를 상속해서 요청마다 딱 한 번만 실행되도록 했다. 토큰이 유효하면 `SecurityContextHolder`에 인증 정보를 넣어줘서, 이후 컨트롤러에서
`@UserInfo CustomUserDetails`로 현재 유저를 꺼낼 수 있다. 토큰이 만료 직전이면 새 토큰을 응답 쿠키에 실어서 자동 갱신도 처리했다.

**Security 설정 요점**

- 세션 정책: `STATELESS` (서버가 세션 안 만듦)
- `/auth/**`는 permitAll, 나머지는 모두 인증 필요
- CSRF 비활성화 (JWT 방식이라 불필요)

## Boot Camp 자가 점검

### 1️⃣ 현재 내가 가능한 기술 정리하기

- JAVA 문법
    - 저는 주 랭귀지가 NodeJS 라 Java 가 손에 익힐 정도로 자연스럽지는 않습니다. 하지만 실무에서의 Java Spring Boot 를 익힌 경험으로 구현하고자 하는 기능은 문법을 구글링하며 구현할 수
      있는 정도입니다.
- 객체지향 개념 설명
    - 실무에서 NestJS 로 깊은 부분까지 제대로 구현해봤고 Java Spring Boot 경험 역시 있기 때문에 객체지향에 대해서는 잘 설명할 수 있습니다.
- 가능한 기술
    - Java Spring Boot
        - CRUD 구현
        - JPA
        - Spring Security
    - Docker
    - k3s (경량화된 Kubernetes)
    - Redis (단순히 KV Store 의 메모리 db 로써 실무에서 이용만 해봤습니다)
    - Github Actions
- 부족한 기술
    - 테스트 코드 작성 경험 부족
    - Kafka, 메시지 큐, 클라우드 (AWS, GCP, …)
    - 부하 테스트 (Gatling 은 실무 경험 있지만, 전체적인 부하 테스트 코드 작성 능력은 부족합니다.)
